The .nbm format

.nbm (Noble Model) is Workflow's only model file. There is no separate checkpoint format.

It is a zip archive:

EntryContent
meta.jsonformat version, Workflow version, creation time, architecture spec (stages, operations, input shape), classes (names), detection (head configuration) and training (epoch, target epochs, best epoch, history, configuration)
weights.ptthe inference weights (the EMA weights when training used EMA), read with weights_only=True so loading never runs code
train.pt *(only after training)*optimizer state, the raw (non-EMA) weights and the EMA update count, so training continues exactly

A .nbm can be loaded for inference (wf.load), fine-tuned, or used to continue training towards a new epoch target. The learning-rate schedule is a function of progress, so its "state" is the epoch and the target stored in training; there is nothing else to restore.

Files are written atomically (a .part file, then renamed), so an interrupted save never leaves a corrupt model.

model.save("noble.nbm")
m = wf.load("noble.nbm")        # architecture + weights, no source needed
model.load("noble.nbm")         # weights into an identical architecture (else SerializationError)

The architecture spec records every operation and its arguments, so any model, including ones using custom wf.Op subclasses that are importable, can be rebuilt from the file alone.
