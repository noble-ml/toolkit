Changes

0.8.0

  • Training on Modal's cloud GPUs: model.train(data, device="modal") (also "modal:H100", or wf.Modal(gpu=, hours=, volume=, cpus=); gpu="cpu" uses Modal CPU cores). The same training runs remotely on cuda, then the checkpoints come back into output and the model holds the trained weights. The dataset is uploaded once to a Modal Volume and reused while unchanged. Checkpoints are kept on the Volume as training goes, so Ctrl+C, errors and the 24-hour limit lose nothing, and wf.Modal.pull(run) fetches them later. wf.fine_tune works too. On the remote machine the dataset is copied to local disk first, and 8 CPU cores are reserved for decoding. See Devices.
  • wf.use(device): choose the device once (wf.use("cuda"), wf.use("modal:a100"), wf.use(train=..., run=...), or with wf.use(...):). Calls without device= use it. The environment variables WORKFLOW_DEVICE / WORKFLOW_TRAIN_DEVICE do the same outside the code. A Modal device changes only training. The training panel shows where the device came from. See Devices.
  • CLI: workflow init --device modal:A100 (the notebook now sets its device once with wf.use(DEVICE), so evaluation stays local while training goes to Modal; a misspelt device is caught when the notebook is written). workflow devices also shows Modal (installed, signed in) and the current default with where it comes from. Generated scripts and workflow predict / eval follow WORKFLOW_DEVICE when --device isn't given.
  • A device= left out no longer pins the model to "auto"'s choice for later calls; only devices you name stick.

0.7.1

  • workflow library: every entry now has a plain-words explanation and an example (model.plot and the recipes were missing them). The cookbook's Felix part moved to Felix's own cookbook (felix library).

0.7.0

  • wf.recurrent(*layers, steps=n): a looped convolutional block (like a looped transformer): the same layers run n times with shared weights, for more depth without more parameters (at the cost of latency). The first convolution sets the width every convolution inside must keep; a projection handles a different input width at step 1; BatchNorm keeps running statistics per step. See Composition.
  • Fine-tuning: wf.fine_tune(model_or_path, data, freeze=...) starts a new run from a trained model's weights (and re-targets the head if the dataset's classes differ); freeze=N / freeze="backbone" keeps layers fixed; model.set_classes(names). On a small new dataset: mAP50 0.92 fine-tuned vs 0.005 from scratch. See Training.
  • A training set whose images were all exported without annotations now says so, instead of "the split is empty".

0.6.0

  • model.labels(), wf.labels("model.nbm") and workflow labels MODEL.nbm [--json]: what a model detects, as class ids and names (the file forms read only metadata).
  • Works with Felix 1.0 (the dataset-engineering redesign): Felix datasets now carry provenance, licences and annotation status. Images exported without any annotation (status "none") are left out of training instead of being learned as pictures with nothing in them; Felix images are Pillow images.
  • wf.practice_dataset(path): the starter notebook's practice dataset (circles, squares, triangles with boxes), drawn with Pillow and stored through Felix's acquire / export. It replaces Felix's removed synthetic generator.
  • Felix 1.0 can annotate datasets with your Workflow models: fx.annotate(model=wf.load("model.nbm")).

0.5.1

  • Sharded datasets (a folder of Felix .sh_felix shards) train one shard at a time: the shard in use in memory, the next one loading in the background, each dropped after its last batch. Shards come in a new random order every epoch with the pictures shuffled inside each; resume stays exact. Needs Felix 0.7.
  • wf.inference and workflow predict recognise shard folders and class folders as datasets.

0.5.0

  • Classification: wf.head(classes=N, type="cls") gives one label per picture (optional 1×1 widening to channels, global average pooling, a fully connected layer). model.train then uses softmax cross-entropy with label smoothing, random-crop augmentation and reports top-1 / top-5 accuracy; wf.eval gives accuracy per class and a confusion matrix; model.predict returns a ClassResult (class_name, confidence, top, probabilities); wf.inference, workflow predict, the webcam and ONNX export all work with it. See Classification.
  • Training data for it: ImageNet-style class folders, read directly by Felix 0.6 (fx.load("animals/")).
  • CUDA 2–2.3× faster: implicit-GEMM convolutions (no im2col copies, no layout transposes, conflict-free vectorised tiles), parallel BatchNorm reductions and fused BatchNorm + activation. Same fp32 results (all operations match the CPU core to 4.5e-7).
  • CUDA uses the GPU's primary context, so Workflow and PyTorch (or any CUDA library) can share one process.
  • benchmarks/: vs_pytorch.py (the same network traced and replayed in PyTorch, checked against float64, then timed), profile_backend.py, device_check.py, conv_check.py, conv_speed.py.

0.4.2

  • workflow library: a full-screen browser of every layer, block and tool, in the CLI's look. Left: everything, grouped, with the arguments under each name; type to search. Right: the full entry (what it does, the toddler-words explanation, why, examples, the catch, the exact signature). felix library does the same for Felix.
  • wf.Residual(..., shortcut="auto") is the new default: when the layers change channels or size, the shortcut becomes a matching 1×1 Conv2D + BatchNorm2D by itself. Also shortcut="identity", shortcut=False (no shortcut), or any layer / wf.stack(...) as your own shortcut. Models saved before load unchanged.

0.4.1

  • Upgrading Workflow while a notebook kernel (or any Python session) still has the old version loaded now stops with a plain "restart the session" message, instead of failing part-way with errors such as 'Batches' object has no attribute 'iterate'.

0.4.0

  • CPU training 3.3–4× faster (the workflow init model on a 2-core 2012 laptop: 3.5 → 11.7 images/s at 320 px, 0.76 → 3.0 at 640 px), with the same results:
  • convolutions use a packed, register-blocked matrix multiply (6×16 micro-kernel; AVX, AVX2+FMA or NEON) that reads the picture directly (no im2col copy), forward, weight gradient and stride-1 input gradient;
  • BatchNorm + activation run as one vectorised pass and the BatchNorm output is no longer stored;
  • vectorised exp / sigmoid / SiLU; multi-threaded upsample and pooling backward; vectorised max pooling.
  • Less memory: backward frees what each layer kept as soon as it is used (640 px batch 16: 2.8 GB in 0.3 → 1.8 GB).
  • low_memory= for model.train: recompute activations instead of keeping them (identical gradients and BatchNorm statistics, ~30% slower, ~40% less memory). On CPU it is chosen automatically when needed, and a run that cannot fit stops before it starts, with the batch size that fits.
  • Crash protection: autosave of last.nbm every 10 minutes inside an epoch (autosave=), exact resume at the saved step (reproducible shuffling), Ctrl+C and SIGTERM stop at the end of the step, other errors save first, checkpoints are flushed to disk before replacing the old file.

0.3.9

0.3.8

0.3.7

  • The next batch is prepared while the current one trains (all devices).
  • Training shows validation loss, and a per-epoch table (0.3.6).

New

  • Own compute engine: native C CPU core, own CUDA kernels, experimental Apple GPU (MLX).
  • Layers: DepthwiseConv2D, PointwiseConv2D, SeparableConv2D, TransposeConv2D, DilatedConv2D; explicit numeric and asymmetric padding.
  • Blocks: SPP, SE, CBAM, Focus; Bottleneck is now a real reduce / spatial / expand bottleneck.
  • Composition: wf.parallel, wf.feature, wf.PAN over pyramids.
  • Quantisation: wf.QAT, post-training quantisation, workflow quantize, INT8 / FP16 .nbm and ONNX.
  • Errors with what / why / fix everywhere.
