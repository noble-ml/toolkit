Architecture analysis

Everything here works on the architecture alone: no data, no training, no forward pass on real tensors.

model.summary()

totals = model.summary()                      # prints a table, returns the totals
model.summary(input=(3, 416, 416))            # for another input size

stage / # / operationwhere the operation sits (position inside its stage)
outputits output shape (C, H, W); several for multi-output operations

Totals: parameters (trainable / non-trainable), GFLOPs, and memory.

model.analyze(input=None)

Returns an Analysis with the same numbers as data: .params, .trainable, .non_trainable, .macs, .flops, .param_bytes, .act_bytes, .peak_bytes, and .ops (one entry per operation with .macs, .trainable, .out_shapes, ...).

How the numbers are defined:

  • MACs count convolutions (they dominate). BatchNorm folds into the convolution at inference; activations, pooling, upsampling and additions are not counted. FLOPs = 2 × MACs. They are measured by running the architecture on torch's meta device, so they follow the real computation of every block (including custom operations) and cost no memory or time.
  • Non-trainable parameters are BatchNorm running statistics.
  • Memory is an fp32, per-image estimate: *weights*; *activations* = the sum of every operation's output (what training keeps for backpropagation); *inference peak* = the most tensors alive at once when the forward pass frees tensors as soon as they are unused. Multiply the per-image numbers by the batch size.

Drawing the graph

model.plot()                                   # opens the image; returns a PIL image
model.export_graph("architecture.png")         # or .svg
model.export_graph("overview.svg", detail="stages")   # compact: one card per stage

It draws the actual computation graph, with no Graphviz or other tool to install:

  • one card per stage with its output shapes, one row per operation, arrows for the sequential flow;
  • residual shortcuts and branches: Residual, Bottleneck, CSP and SPPF are drawn with their real paths and the + (add) or © (concat) merge;
  • named routing: red edges from the stage/port that publishes a tensor to the operation that reads it, labelled with the tensor name; ports on the right edge of multi-input and multi-output operations;
  • the model input at the top and the model outputs at the bottom.

detail="ops" (default) shows every operation; detail="stages" is the compact overview. PNG files are rendered at 2× for sharpness (scale=). In a notebook model.plot() displays the image inline.
