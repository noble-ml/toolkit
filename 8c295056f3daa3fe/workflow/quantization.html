Quantisation and export

Precisions

PrecisionWeights on diskActivationsTypical size
fp32float32float321×
fp16float16float320.5×
int8int8, one scale per tensor (symmetric)int8 at every convolution input (affine, per tensor)0.25×

INT8 covers every convolution layer (Conv2D, DepthwiseConv2D, PointwiseConv2D, SeparableConv2D, DilatedConv2D, and those inside blocks). TransposeConv2D stays float and is reported with a warning.

QAT: quantisation-aware training

model.train(train, validation=val, epochs=20, quantization=wf.QAT(precision="int8"))

Every training step rounds convolution weights and inputs to the int8 grid (gradients pass straight through), so the model learns weights that survive quantisation, and the activation ranges are tracked while it trains. Usually you fine-tune an fp32 model for a few epochs this way. After it, model.precision is "int8".

Post-training quantisation

model.quantize("int8", calibration=val)       # in place; then model.save(...)

Or from the terminal:

workflow quantize detector.nbm int8 --calibration data.felix     # → detector-int8.nbm
workflow quantize detector.nbm fp16

calibration images fix the activation ranges. Without them only the weights are quantised, with a warning. On the demo detector, INT8 post-training quantisation changed test mAP50-95 from 0.811 to 0.806 and the file from 19.7 MB (with training state) to 1.3 MB.

Exporting

model.save("detector.nbm")                                               # native, current precision
model.export(format="nbm", output="detector-int8.nbm", precision="int8") # real int8 weights
model.export(format="onnx", output="detector.onnx")                      # fp32 ONNX
model.export(format="onnx", output="detector-int8.onnx", precision="int8", calibration=val)
  • ONNX (opset 13) has one input images (batch, C, H, W) and one raw output per head map (output0, output1, ...). The decoding described in Detection is not inside the file. FP16 stores half-precision weights; INT8 uses QuantizeLinear / DequantizeLinear with int8 weights. Checked with ONNX Runtime: fp32 matches Workflow to 1e-5.
  • INT8 .nbm files really store int8 weights and the activation ranges. Loading them gives a model that runs the int8 simulation, so its predictions match the quantised model.
  • Before converting, Workflow validates the input size against the architecture and refuses unknown formats or precisions with an explanation. TorchScript .pt is gone along with PyTorch.
