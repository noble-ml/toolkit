Cookbook

Every tool, explained like you're three, then *why* you'd reach for it and where it goes. Every example writes out all the main arguments (with their defaults) so you can see every knob, even the ones you'd usually leave alone.

Felix makes the pictures. Workflow is the brain that learns to find things in them.

How to read an entry:

  • Toddler words: what it is.
  • Why you'd use it: the reasoning, and where it usually sits.
  • Example: every main argument shown.
  • Watch out: the one mistake people make (when there is one).

---

Part 1 · Felix: making the pictures

fx.class_set

Toddler words: a toy box with a name. Every toy you make inside it is a *kind of thing* the brain must learn to find.

Why you'd use it: the brain can only learn classes you define, and the boxes let you group them (animals, vehicles) so you can later pick "any animal" or "any vehicle" at random. The class name comes from the variable name, so cat = ... makes a class called cat.

with fx.class_set("animals"):
    cat = fx.toolkit.circle(radius=30)              # class "cat"
    dog = fx.toolkit.rectangle(width=50, height=40) # class "dog"

Watch out: shapes made *outside* a class set are not classes: they get drawn but never labelled. That's how you make decoys on purpose.

fx.toolkit.circle, rectangle, polygon

Toddler words: a ball, a box, and a "connect the dots" shape.

Why you'd use it: quick synthetic objects for testing a pipeline, or for detecting simple things (signs, markers, parts). position is only a default spot; usually fx.paint decides where it goes.

ball = fx.toolkit.circle(radius=20, position=None, color="red", name=None)
box  = fx.toolkit.rectangle(width=40, height=30, position=None, color="#1f77b4", name=None)
tent = fx.toolkit.polygon(vertices=[(0, 40), (20, 0), (40, 40)], position=None, color="green", name=None)

Watch out: without color, each class gets its own colour from a palette. Set it when the colour matters.

fx.stack

Toddler words: glue several shapes together into one toy. A big circle, two triangle ears and two dot eyes make one cat, and the brain learns "cat", not "circle" and "triangle".

Why you'd use it: real objects are made of parts. A stack lets you build a recognisable object from simple shapes and still get one class and one box around the whole thing. The class name is the variable name. Each part's position says where its centre goes, measured from the middle of the stack.

with fx.class_set("animals"):
    cat = fx.stack(
        fx.toolkit.polygon(vertices=[(0, 14), (7, 0), (14, 14)], position=(-13, -22), color=None),  # left ear
        fx.toolkit.polygon(vertices=[(0, 14), (7, 0), (14, 14)], position=(13, -22), color=None),   # right ear
        fx.toolkit.circle(radius=22, position=(0, 0), color=None),                                  # head
        fx.toolkit.circle(radius=3, position=(-8, -4), color="black"),                               # eyes
        fx.toolkit.circle(radius=3, position=(8, -4), color="black"),
        position=None, color="#e8a33d", name=None,
    )

Watch out: parts are drawn in order, so put the things that go *on top* (eyes, nose) last. Parts without a colour use the stack's colour; parts with one keep it. Spinning or growing the stack moves all its parts together.

fx.toolkit.image

Toddler words: use a real sticker as a toy. The see-through parts of the sticker don't count as the toy.

Why you'd use it: cut-out photos of real objects (PNG with transparency) look far more like real life than plain shapes. The box is fitted to the visible pixels only, so transparent padding never makes boxes too big.

bike = fx.toolkit.image(source="assets/bicycle.png", width=80, height=None, position=None, name=None)

Watch out: give only width *or* height to keep the proportions; give both to stretch. JPEG stickers need Pillow, and have no see-through parts.

fx.step

Toddler words: the recipe for one picture. Felix follows it again and again, rolling new dice each time.

Why you'd use it: everything you write inside it (background, painting, changes) happens once per image. Make several steps (for example "busy street" and "empty street") and Felix shares the images between them.

with fx.step(size=(640, 640), name=None):
    ...

fx.canvas.background

Toddler words: the paper you draw on: one colour, or a photo.

Why you'd use it: a plain colour is easy to learn; real photos (a folder of them, one picked per image) teach the brain to ignore clutter, which is what you want for real-world use.

fx.canvas.background(color="#eeeeee", image=None)
fx.canvas.background(color=None, image="backgrounds/")    # a different photo each time, cropped to fit

fx.random.*

Toddler words: dice. Every picture rolls them again.

Why you'd use it: variety. A brain that only ever sees a cat in the middle, upright and red will fail on anything else. Randomness in position, size, angle and colour is what makes it robust.

fx.random.uniform(0.5, 2.0, threshold=1.0)    # any number between 0.5 and 2
fx.random.integer(1, 6, threshold=1.0)        # a whole number, like a real die
fx.random.choice("red", "blue", threshold=1.0)
fx.random.position(margin=40, threshold=1.0)  # somewhere on the paper, at least 40 px from the edges
fx.random.color(threshold=1.0)
fx.random.class_set("animals", threshold=1.0) # pick a toy box (any box if no names)
fx.random.class_(None, threshold=1.0)         # pick a toy (from any box, or from the box you pass)

Watch out: threshold=0.5 means "flip a coin first; if it says no, skip it". It's how you get a *varying number* of objects. Each dice call is its own die: the same variable used twice gives the same roll within one picture.

fx.paint

Toddler words: put a toy on the paper.

Why you'd use it: this is what actually places objects. Pass a class, a random class, or a plain shape.

obj = fx.paint(fx.random.class_(None, threshold=1.0), position=fx.random.position(margin=40))

fx.toolkit.transformation

Toddler words: change how the toy looks: spin it, grow it, recolour it, brighten it, fade it.

Why you'd use it: the same as dice: real objects come at all angles, sizes and lighting. Calls add up (two rotations add, two scales multiply).

fx.toolkit.transformation(obj, hue=fx.random.uniform(-20, 20), brightness=fx.random.uniform(0.8, 1.2),
                          rotation=fx.random.uniform(0, 360), scale=fx.random.uniform(0.7, 1.5), opacity=1.0)

Watch out: hue is in degrees around the colour wheel, rotation is in degrees counter-clockwise, and the others are multipliers (1 = unchanged).

fx.gen

Toddler words: take a photo of where every toy is (the answer key). Toys painted *after* the photo are in the picture but not in the answers.

Why you'd use it: it writes the boxes. Painting things after it adds decoys the brain must learn to ignore, which cuts false alarms.

fx.gen()
fx.paint(fx.toolkit.circle(radius=8, color="gray"), position=fx.random.position(margin=0))   # a decoy

fx.make

Toddler words: do the recipe lots of times and put everything in a folder (or one .felix file).

Why you'd use it: this is the moment the dataset is created. Same seed = the exact same dataset, which is handy for comparing models fairly.

fx.make(pairs=1000, output="shapes.felix", seed=7, overwrite=False, quiet=False)

fx.load and its splits

Toddler words: open the dataset. It already has three piles: train (learn from these), val (check while learning), and test (the final exam nobody peeks at).

Why you'd use it: you pass these piles straight to Workflow. Generated datasets are split 80/10/10, the same way every time. Converted datasets keep their own splits.

data = fx.load("shapes.felix")
data.train, data.val, data.test          # the piles
data.classes                             # ['circle', 'square', 'triangle']
data.image(data.stems[0]).save("look.png")

fx.partition / felix partition

Toddler words: cut one big pile into smaller piles, each a complete dataset.

Why you'd use it: share work between machines, make a small dataset for quick tests, or split a converted dataset your own way.

fx.partition("shapes.felix", output=None, parts=4, ratio=None, size=None, by_split=False,
             names=None, shuffle=False, seed=0, pack=None, overwrite=False)
fx.partition("shapes.felix", ratio=(80, 10, 10), names=["train", "val", "test"], shuffle=True, seed=1)
felix partition shapes.felix --size 100

Watch out: choose exactly one of parts, ratio, size or by_split.

Other Felix commands

Toddler words: look inside a box, zip it up, unzip it, and turn someone else's box into yours.

Why you'd use it: checking what you made, sending one file instead of thousands, and training on real Roboflow datasets.

felix info shapes.felix
felix pack ./dataset -o dataset.felix
felix unpack dataset.felix -o ./dataset
felix convert coco ./roboflow-export -o data.felix

Part 2 · Workflow: the brain's building blocks

wf.stack

Toddler words: line up blocks. The picture goes through them one after another, like a slide with bumps.

Why you'd use it: it's the model itself (the outermost one) and also any group of layers you want to treat as one. input is the picture size the model is built and checked for.

model = wf.stack(
    wf.Conv2D(16, kernel_size=3, stride=1, padding="same"),
    wf.BatchNorm2D(),
    wf.SiLU(),
    wf.feature("p1"),
    input=(3, 640, 640),
)

Watch out: you never say how many channels go *in* to a layer. Workflow works that out.

padding (used by every layer with a window)

Toddler words: a cushion of empty pixels around the picture so the edges don't get squished away. You pick one of two words: "same" (put a cushion on, keep the picture the same size) or "valid" (no cushion, the picture shrinks a little).

Why you'd use it: without a cushion, every 3×3 window eats one pixel from each edge, so the picture shrinks a bit at every layer. "same" stops that, which keeps sizes easy to reason about: a stride-1 layer keeps the size, and a stride-2 layer exactly halves it (rounding up). Almost every layer in a detector uses "same". "valid" (the default) is for when you *want* the picture to shrink, or want the window to only ever see real pixels.

wf.Conv2D(32, kernel_size=3, stride=1, padding="same")    # 256×256 in → 256×256 out
wf.Conv2D(32, kernel_size=3, stride=2, padding="same")    # 256×256 in → 128×128 out
wf.Conv2D(32, kernel_size=3, stride=1, padding="valid")   # 256×256 in → 254×254 out

Watch out: numbers like padding=1 are not accepted. The error tells you which word to use (1 meant "same" for a 3×3, 0 meant "valid").

wf.Conv2D

Toddler words: little magnifying glasses that slide over the picture, each looking for one kind of pattern (an edge, a corner, a stripe). The first number is out_channels: how many different glasses, so how many channels come *out*. 32 means 32 glasses, so 32 channels come out.

Why you'd use it: it's *the* building block. Early convs find edges; later ones find parts and whole objects. stride=2 takes big steps, halving the picture; that's how a backbone goes from big-and-shallow to small-and-deep. You never write how many channels come *in*: Workflow reads that from the layer before.

wf.Conv2D(32, kernel_size=3, stride=1, padding="same")    # 32 channels out, same size
wf.Conv2D(64, kernel_size=3, stride=2, padding="same")    # 64 channels out, half size: a "downsampling" step
wf.Conv2D(out_channels=64, kernel_size=3, stride=2, padding="same")   # the same, with the name written out

wf.DepthwiseConv2D

Toddler words: one magnifying glass per colour channel, and each one only looks at its own channel.

Why you'd use it: it's very cheap. Mobile-style models use it to look around spatially for almost no cost, then mix the channels with a pointwise conv.

wf.DepthwiseConv2D(kernel_size=3, stride=1, padding="same")    # keeps the channel count

wf.PointwiseConv2D

Toddler words: a 1×1 glass. It doesn't look around; it just mixes the channels at each spot.

Why you'd use it: changing the number of channels cheaply: squeezing before expensive work, or matching channels before an add.

wf.PointwiseConv2D(64)       # kernel 1, stride 1, padding 0 are fixed: that's what "pointwise" means

wf.SeparableConv2D

Toddler words: depthwise, then pointwise: look around, then mix.

Why you'd use it: a drop-in for Conv2D that does nearly the same job for a fraction of the maths. Good for small or fast models.

wf.SeparableConv2D(64, kernel_size=3, stride=1, padding="same")

wf.DilatedConv2D

Toddler words: a magnifying glass with gaps between its eyes, so it sees farther without costing more.

Why you'd use it: a bigger view (more context) without shrinking the picture or adding work. Useful late in a network or for big objects.

wf.DilatedConv2D(32, kernel_size=3, dilation=2, stride=1, padding="same")   # sees a 5×5 area, keeps the size

wf.TransposeConv2D

Toddler words: a magnifying glass that makes the picture *bigger* (it un-squishes), and learns how.

Why you'd use it: growing a small, smart map back to a bigger size, for example in a neck. Unlike Upsample, which just copies pixels, it *learns* how to fill in the new pixels.

wf.TransposeConv2D(32, kernel_size=2, stride=2, padding="valid")   # exactly twice the height and width
wf.TransposeConv2D(32, kernel_size=4, stride=2, padding="same")    # also twice, blending neighbours more smoothly

Output size: with "same" it is exactly size × stride; with "valid" it is (size − 1) × stride + kernel_size. With kernel_size=2, stride=2 both give exactly double, which is why those are the defaults.

Watch out: "same" needs kernel_size at least as big as stride (the error says so). It stays float in int8 models (Workflow warns you); use Upsample + Conv2D if everything must be int8.

wf.BatchNorm2D

Toddler words: keeps the numbers from getting too big or too small, so learning doesn't wobble.

Why you'd use it: almost always right after a convolution: Conv2D → BatchNorm2D → activation. Models train faster and more reliably with it. The conv before it automatically drops its bias, which the BatchNorm would cancel anyway.

wf.BatchNorm2D()         # channels are worked out for you

wf.ReLU, wf.LeakyReLU, wf.SiLU, wf.Sigmoid

Toddler words: mood filters. ReLU says "no sad numbers, make them zero". LeakyReLU says "a tiny bit of sad is okay". SiLU is a smooth ReLU. Sigmoid squishes everything between 0 and 1.

Why you'd use it: without them, stacking layers is no smarter than one layer. SiLU is the modern default for detectors; ReLU is the cheapest; Sigmoid is for gates and probabilities, not between layers.

wf.ReLU()
wf.LeakyReLU(slope=0.1)
wf.SiLU()
wf.Sigmoid()

wf.MaxPool2D, wf.MinPool2D, wf.AvgPool2D

Toddler words: shrink the picture by looking at little squares and keeping one number from each. Max keeps the loudest pixel, Min keeps the quietest, Avg keeps the average.

Why you'd use it: a cheap way to make the picture smaller (or smoother) with no weights to learn.

  • Max answers "is the pattern anywhere in here?". It is the usual choice, and what SPPF uses.
  • Min answers "is anything *missing* or dark here?", for dark objects on light backgrounds, gaps or holes.
  • Avg smooths things out and keeps the overall level.
wf.MaxPool2D(kernel_size=2, stride=None, padding="valid")   # stride defaults to kernel_size: half the size
wf.MaxPool2D(kernel_size=5, stride=1, padding="same")       # same size: every pixel becomes its 5×5 neighbourhood's max
wf.MinPool2D(kernel_size=3, stride=2, padding="same")       # half the size, keeping the smallest values
wf.AvgPool2D(kernel_size=3, stride=1, padding="same")       # same size, just smoothed

Watch out: the cushion pixels from "same" never win a max or a min, but they count as zero in an average, so averages at the very edge come out a little darker.

wf.Upsample

Toddler words: make the picture bigger by copying each pixel.

Why you'd use it: cheap resizing with nothing to learn, usually before joining a small map to a big one.

wf.Upsample(scale=2)

Part 3 · Workflow: bigger blocks

wf.Bottleneck

Toddler words: squeeze the picture thin (fewer channels), look around, puff it back up, then add the original back so nothing gets lost.

Why you'd use it: to make a network deeper without making it slow. The expensive 3×3 look-around happens on the thin version, and the added shortcut keeps learning stable in deep stacks.

wf.Bottleneck(out_channels=None, kernel_size=3, stride=1, reduction=2, shortcut=True)   # same shape out as in
wf.Bottleneck(out_channels=128, kernel_size=3, stride=2, reduction=2, shortcut=True)    # 128 channels out, half size

Watch out: when out_channels or stride change the shape, the shortcut gets a 1×1 projection automatically, so you never have to match the shapes yourself.

wf.CSP

Toddler words: split into two paths. One does hard work (bottlenecks), one takes it easy. Then glue them together.

Why you'd use it: most of the accuracy of a deep stack of bottlenecks at a lot less cost. It's the standard backbone block after each downsampling conv.

wf.CSP(out_channels=None, n=1, shortcut=True)      # n = how many bottlenecks on the busy path

wf.SPP, wf.SPPF

Toddler words: look at the picture through small, medium and big windows at the same time, then glue what you saw.

Why you'd use it: at the end of the backbone, so the brain sees both details and the big picture. SPPF gets the same result faster with three chained small pools, so prefer it.

wf.SPP(out_channels=None, kernels=(5, 9, 13))
wf.SPPF(out_channels=None, kernel_size=5)

wf.SE

Toddler words: each channel asks "am I important for *this* picture?" and turns its own volume up or down.

Why you'd use it: a small, cheap accuracy boost, usually after a backbone block. It learns to pay more attention to the channels that matter for the image at hand.

wf.SE(reduction=16)       # how much the "am I important?" helper squeezes; 16 is the classic value

wf.CBAM

Toddler words: SE, plus "which *spots* in the picture matter?": a spotlight for channels and places.

Why you'd use it: like SE, but it also helps with *where*, which suits detection. Costs a bit more.

wf.CBAM(reduction=16, kernel_size=7)

wf.Focus

Toddler words: cut the picture into 2×2 tiles and stack the tiles as channels: half the size, nothing thrown away.

Why you'd use it: as the very first layer, a fast way to shrink a big input without losing pixels.

wf.Focus(out_channels=32, kernel_size=3)

Watch out: the input height and width must be even.

Part 4 · Workflow: wiring

wf.Residual

Toddler words: do some stuff, then add what you started with. "Remember where you came from."

Why you'd use it: to build your own residual block. It lets very deep models train, because the brain can learn "a small change to the input" instead of a whole new picture.

wf.Residual(
    wf.Conv2D(64, kernel_size=3, stride=1, padding="same"),
    wf.BatchNorm2D(),
    wf.SiLU(),
    shortcut=None,                                    # same shape in and out: add the input as it is
)

wf.Residual(
    wf.Conv2D(128, kernel_size=3, stride=2, padding="same"),
    wf.BatchNorm2D(),
    wf.SiLU(),
    shortcut=wf.Conv2D(128, kernel_size=1, stride=2, padding="valid"),   # shape changes → project the input to match
)

Watch out: both paths must end the same shape. If they don't, the error tells you the exact shortcut= to add.

wf.parallel

Toddler words: give the same picture to several friends, then glue (or add up) their answers.

Why you'd use it: let the brain look at the same thing in different ways at once (small and big windows, for example), Inception-style.

wf.parallel(
    wf.Conv2D(16, kernel_size=1, stride=1, padding="valid"),
    wf.Conv2D(16, kernel_size=3, stride=1, padding="same"),
    merge="concat",                                   # or merge="add" (then the outputs must match)
)

wf.feature

Toddler words: stick a note with a name on the current picture so you can grab it later.

Why you'd use it: detectors need maps from several depths (big and detailed, small and smart). You name them in the backbone and use them in the neck.

wf.feature("p3")
wf.feature(("n3", "n4", "n5"))        # after FPN/PAN: one name per map of the pyramid

wf.concat, wf.add

Toddler words: grab named notes and glue them side by side (concat) or add them up (add).

Why you'd use it: to hand-build skip connections or necks. Concat keeps both sets of channels (more information, more channels); add mixes them (same channels, cheaper).

wf.concat("p3", "up")      # needs the same height and width; channels add up
wf.add("a", "b")           # needs identical shapes

wf.FPN

Toddler words: big pictures see small details; small pictures know *what* things are. FPN passes the "what" knowledge down into the big pictures.

Why you'd use it: so small objects (found on the big maps) are recognised as well as large ones. It takes your named maps in any order, any channel counts, and handles the resizing and channel matching itself.

wf.FPN("p3", "p4", "p5", channels=64)      # channels=None uses the smallest input's channel count

wf.PAN

Toddler words: the other way round: it passes the sharp details back up to the small pictures.

Why you'd use it: right after FPN, so the maps that find big objects also get precise edges. FPN + PAN is the classic modern neck.

wf.PAN(channels=64)                        # works on the pyramid FPN just produced

wf.head

Toddler words: the mouth. For every spot it says "there's a cat here, this big, and I'm this sure".

Why you'd use it: it's what turns features into boxes. It must be the last layer, and classes must match your dataset (Workflow checks).

wf.head(classes=3, channels=None)          # channels=None: as wide as each incoming map

Part 5 · Workflow: using the brain

model.summary()

Toddler words: "tell me about yourself": every layer, how big, and how much work it does.

Why you'd use it: before training, to check the shapes come out as you expect and the model isn't accidentally huge. It builds the model, so shape mistakes show up here, not halfway through training.

model.summary(input=None, show=True)       # input=(3, 416, 416) checks another size

model.export_graph

Toddler words: draw a picture of the brain.

Why you'd use it: to see your wiring (shortcuts, branches, which feature goes where) or to share it. SVG for documents, PNG for quick looks.

model.export_graph("brain.png", detail="layers", scale=2)     # detail="compact" for one row per layer

model.device

Toddler words: pick which helper does the maths: the computer's own brain ("cpu"), a big NVIDIA graphics card ("cuda"), any graphics card ("gpu"), or a Mac's graphics chip ("mps", still learning to walk).

Why you'd use it: GPUs are much faster for training. Usually you just pass device= to train or predict instead.

model.device("cuda")      # or "cpu", "gpu", "mps", "auto"
model.device()            # which one am I on?

Watch out: if you ask for a GPU that isn't there, you get an error saying why, never a silent switch to CPU.

model.train

Toddler words: look at lots of pictures and their answers, again and again, until you get good. Press Ctrl+C and it saves before stopping.

Why you'd use it: this is learning. The defaults (optimizer, learning-rate schedule, loss, augmentation, checkpoints) are sensible, so most of the time you only set the data and epochs.

model.train(data.train, validation=data.val, epochs=50, batch_size=16, lr=1e-3, device="auto",
            img_size=None, optimizer="adamw", patience=30, save_every=5, output="runs/train",
            quantization=None, augment=True, ema=True)

Watch out: epochs means "train *until* epoch N". To continue a model that reached 50, ask for epochs=80 to get 30 more; epochs=30 would do nothing.

wf.eval

Toddler words: a report card. Without a test: "how big and how fast am I?". With a test: "how many do I get right?".

Why you'd use it: before training to compare architectures (size, speed); after training to measure accuracy on the test pile. It never changes the model.

wf.eval(model, dataset=None, device=None, img_size=None, batch_size=8, show=True)
wf.eval(model, dataset=data.test)              # adds mAP50, mAP50-95, precision, recall

wf.QAT

Toddler words: practise with smaller, rounder numbers while learning, so the brain still works after it's shrunk.

Why you'd use it: when you'll ship an int8 model (smaller, faster on small devices). Usually a short fine-tune *after* normal training: it starts from your trained weights.

model.train(data.train, validation=data.val, epochs=55, quantization=wf.QAT(precision="int8"))   # 5 epochs after 50

model.quantize / workflow quantize

Toddler words: shrink a finished brain so it's small and fast. Show it some pictures first (calibration) so it learns how big the numbers get.

Why you'd use it: the quick way to int8 or fp16 without retraining. Try it first; use QAT if accuracy drops too much.

model.quantize("int8", calibration=data.val)     # "fp16" needs no calibration
workflow quantize detector.nbm int8 --calibration shapes.felix

model.save, wf.load, model.load

Toddler words: put the brain in a box (.nbm) and take it out again later.

Why you'd use it: keep a trained model, share it, or continue training it. The box holds the layers, weights, class names and training progress.

model.save("detector.nbm")
model = wf.load("detector.nbm")       # rebuilds everything from the box
model.load("detector.nbm")            # fills a model you already built the same way

model.export

Toddler words: pack the brain for other programs (ONNX), or make a smaller box.

Why you'd use it: ONNX runs in many runtimes (ONNX Runtime, mobile, servers); an int8 .nbm is the smallest Workflow file.

model.export(format="onnx", output="detector.onnx", precision="fp32", calibration=None, img_size=None)
model.export(format="nbm", output="detector-int8.nbm", precision="int8", calibration=data.val)

model.predict

Toddler words: "what's in this picture?". It draws boxes and puts the pictures and a list of answers in results/.

Why you'd use it: to actually use the detector, on one image, many images, or video frames.

r = model.predict("photo.jpg", device=None, confidence=0.25, iou=0.45, img_size=None,
                  output="results/", max_detections=300)
r.classes, r.confidences, r.xyxy
r.show()

Watch out: raise confidence for fewer, surer boxes; lower iou if one object gets several boxes. output=None saves nothing, which is handy for video.

Errors

Toddler words: when something is wrong, Workflow tells you what broke, why, and how to fix it, like a kind teacher.

Why it matters: you fix it from the message instead of digging through code. The first line also names the layer.

layer 4 (Residual): Residual cannot add its two paths.
  why: the layers output (16, 15, 15) but the shortcut carries (8, 30, 30); addition needs identical shapes.
  fix: ... project the input with shortcut=wf.Conv2D(16, kernel_size=1, stride=2).

workflow init

Toddler words: "give me a notebook that already works." It writes a Jupyter notebook with a small brain, a report card before and after learning, and saving.

Why you'd use it: the fastest way to start a new detector, or to show someone how Workflow fits together. Every step is a cell you can read and change; the model is a flat list of layers you can grow. Without a dataset it makes a practice one, so the first run always works.

workflow init detector.ipynb --dataset data.felix --img-size 256 --epochs 30 --device auto

Watch out: the image size must be a multiple of 32 (the starter model halves the picture four times).

Part 6 · Recipes: how the pieces fit

A downsampling step (the most common pattern in a backbone): three lines that halve the picture and add channels. You'll see it again and again in the detector below.

wf.Conv2D(64, kernel_size=3, stride=2, padding="same"),
wf.BatchNorm2D(),
wf.SiLU(),

A small detector: the backbone halves the picture five times, naming three depths with wf.feature; SPPF widens the view; FPN + PAN mix the named maps; the head finds the boxes.

model = wf.stack(
    # stem: 256 → 128
    wf.Conv2D(16, kernel_size=3, stride=2, padding="same"),
    wf.BatchNorm2D(),
    wf.SiLU(),

    # 128 → 64
    wf.Conv2D(32, kernel_size=3, stride=2, padding="same"),
    wf.BatchNorm2D(),
    wf.SiLU(),
    wf.CSP(n=1),

    # 64 → 32: good for small objects
    wf.Conv2D(64, kernel_size=3, stride=2, padding="same"),
    wf.BatchNorm2D(),
    wf.SiLU(),
    wf.CSP(n=2),
    wf.feature("p3"),

    # 32 → 16: medium objects
    wf.Conv2D(128, kernel_size=3, stride=2, padding="same"),
    wf.BatchNorm2D(),
    wf.SiLU(),
    wf.CSP(n=2),
    wf.feature("p4"),

    # 16 → 8: large objects
    wf.Conv2D(256, kernel_size=3, stride=2, padding="same"),
    wf.BatchNorm2D(),
    wf.SiLU(),
    wf.SPPF(kernel_size=5),
    wf.feature("p5"),

    # neck and head
    wf.FPN("p3", "p4", "p5", channels=64),
    wf.PAN(channels=64),
    wf.head(classes=3),

    input=(3, 256, 256),
)

Train, then shrink for deployment:

model.train(data.train, validation=data.val, epochs=50)
wf.eval(model, dataset=data.test)
model.train(data.train, validation=data.val, epochs=55, quantization=wf.QAT(precision="int8"))
model.export(format="nbm", output="detector-int8.nbm", precision="int8")
