Model is a regular torch.nn.Module, so .parameters(), .eval(), .to(), torch.compile(model) and friends work as usual.

Summary

Parameters are split into trainable and non-trainable (BatchNorm running statistics). The table lists top-level operations; a block's row includes everything inside it.

FLOPs/MACs, memory and graph drawing: see Analysis.

Devices and speed

  • "auto" prefers CUDA, then Apple MPS, then CPU. An unavailable request raises DeviceError with what *is* available. workflow devices shows the same from the terminal.
  • On CUDA, Workflow enables cuDNN autotuning, TF32 and the channels-last memory layout.
  • Run inference under torch.inference_mode(); intermediate tensors are freed as soon as they are unused, which keeps memory low.
  • torch.compile(model) works for extra speed on supported setups.
  • Training uses mixed precision on CUDA automatically; model.predict uses fp16 on CUDA.

Measured on an Apple M-series laptop, 640×640, batch 8, a small model: ~25 img/s on CPU, ~190 img/s on MPS. model.benchmark() measures your own model on your own device.
