Routing

Ordinary stages need no wiring: each reads the previous stage's output. Routing is for everything else, and it is always by name; Workflow never picks a feature map by position or channel count.

Names

Every tensor that can be referenced has one name:

  • the model input is "input" (reserved)
  • a stage publishes its final output under the stage name
  • an operation that produces several tensors publishes them under the names given by its outputs=

All published names live in one namespace and must be unique.

Reading earlier outputs

Whole stage from another point: input= on the stage.

wf.Stage("head", wf.Conv2D(64, 32, 1), input="p2")     # reads p2, not the previous stage

Operations that combine tensors (Concat, Add, FPN, PAN, or your own) declare inputs=("a", "b"). Such an operation reads exactly those names and ignores the running tensor.

Several outputs

An operation declares outputs=("n3", "n4", "n5"), one name per tensor it returns. Rules:

  1. It must be the last operation of its stage.
  2. The stage then publishes those names, and not its own name.
  3. The next stage can't silently take "the output": it must say which, with input="n3" or an operation with inputs=(...).
wf.Stage("neck", wf.FPN(inputs=("p3", "p4", "p5"), channels=128, outputs=("n3", "n4", "n5"))),
wf.Stage("pan",  wf.PAN(inputs=("n3", "n4", "n5"), channels=128, outputs=("m3", "m4", "m5"))),
wf.Stage("head3", wf.Conv2D(128, 64, 3, padding=1), input="m3"),

Here neck publishes n3, n4, n5 (not neck), and pan reads exactly those. Full runnable version: examples/phase2.py.

Custom operations

Subclass wf.Op, implement forward(*tensors) and infer(*shapes), set self.inputs / self.outputs in __init__. Anything built this way is routed, validated and serialized like a built-in. (See tests/test_phase1.py for tiny examples.)
