Devices and backends

Workflow computes with its own engine. PyTorch is not used.

DeviceBackendStatus
"cpu"native C core: im2col + cache-blocked GEMM, depthwise kernels, a thread pool, fused BatchNorm / activation kernelsstable
"cuda", "cuda:N"Workflow's own CUDA kernels (register-tiled GEMM convolution, BatchNorm, pooling, ...), shipped as PTX and run through the NVIDIA driverstable
"gpu"CUDA if present, else the Apple GPU
"mps"Apple GPU through MLX, Apple's open-source Metal array library (pip install mlx)experimental: warns when used
"auto"CUDA, then CPU (experimental MPS is never picked implicitly)
model.device("cuda")                           # or model.train(..., device="cuda")
workflow devices                               # what this machine has, and why something is unavailable

A requested device that isn't available raises a DeviceError explaining why (no driver, no MLX, no GPU) and what to do. Workflow never silently runs on another device than the one you asked for.

Correctness

Every operation and gradient is tested against PyTorch on the CPU (tests/test_core.py, PyTorch as a test oracle only), and every accelerator is tested against the CPU (tests/test_parity.py). On a GTX 1050 all 26 operations match the CPU core to 4e-7 relative error, and on Apple MLX to 6e-7.

Threads

The CPU core uses one thread per core, up to 16.
