Detection and inference

The head

wf.head(classes=80) ends a detection model. It works on the pyramid coming from wf.FPN / wf.PAN (or on a single map). Per map it applies two 3×3 Conv-BN-SiLU layers and a 1×1 convolution with 4 + 1 + classes output channels:

ChannelsMeaning
0-3distances from the cell centre to the left, top, right and bottom box edges, in units of the map's stride (softplus keeps them positive)
4confidence (objectness) logit
5…one logit per class

It is anchor-free, and each map's stride is derived from the image and map sizes, so any input size the architecture accepts works. classes is part of the architecture; training checks it against the dataset.

Annotations

Workflow reads boxes exactly as Felix stores them (bbox: [x, y, width, height] in pixels, class_id), for generated and converted datasets alike. Nothing is rewritten on disk.

Default loss

You never configure it for ordinary training:

  • Each object is assigned to the pyramid level whose stride suits its size (up to 8× the stride); cells inside the box within 1.5 strides of its centre are positives, every object keeps at least its centre cell, and the smaller object wins where boxes overlap.
  • Loss = 5 × (1 − GIoU) on positive cells + binary cross-entropy for confidence (positives 1, everything else 0) + binary cross-entropy for the classes, normalised by the number of positives.
  • model.train(..., loss_weights=(box, confidence, classes)) changes the weights if you need to.

Inference: wf.inference

The normal way to use a trained model:

model = wf.load("detector.nbm")
run = wf.inference("photo.jpg", model, "results/")

wf.inference(source, model, output) works out what source is on its own:

sourceWhat runs
an image (.png, .jpg, .jpeg, .bmp, .webp)that image
a video (.mp4, .mov, .avi, .mkv, .webm, ...)every frame; the annotated copy is an .mp4 (needs opencv-python)
a folderone image or video from it, picked at random (all=True: every one, not subfolders)
a Felix dataset (.felix file or dataset folder)its test split (val if there is no test split, everything if there are no splits), and from it one image picked at random (all=True: every one)
a loaded dataset or split (data, data.val, ...)the same: one random image of the test split, or of exactly the split you pass (all=True: every one)
a list of any of theseexactly the items in the list

Datasets and folders are usually many pictures, so by default wf.inference takes one random example to look at: run it again for another, or pass all=True to process them all.

Choose a different split of a dataset with split="val" or split="train", or by passing data.val yourself. model can also be the path of a .nbm.

It returns an Inference: .images (a Results for each image, see below), .videos ({name: per-frame detections}), .output, .json and .json_path. Names never collide: two inputs called photo.png become photo.png and photo_2.png. From the terminal: workflow predict detector.nbm clip.mp4 (same rules, --all, --split, -o).

Prediction in memory: model.predict

wf.inference is built on model.predict, which you can call directly when you want results in Python without the folder of files:

model = wf.load("detector.nbm")
results = model.predict("image.jpg")
results = model.predict(["image1.jpg", "image2.jpg"])
results = model.predict("image.jpg", device="cuda", confidence=0.25, iou=0.45, img_size=640)
results = model.predict("image.jpg", output="predictions/")
results = model.predict(frame_rgb_array, output=None)              # nothing written: handy inside your own loop
ArgumentDefaultMeaning
sourcerequiredan image path, a PIL / Felix image, an RGB (H, W, 3) uint8 array, or a list of those
deviceauto"cpu", "cuda", "gpu", "mps"; without it the model's device (or the best one) is used
confidence0.25minimum score (confidence × class probability)
iou0.45overlap above which a weaker box of the same class is removed (NMS)
img_sizethe model's inputinference size (int or (H, W)); checked against the architecture
output"results/"folder for annotated images and predictions.json (created if needed); None writes nothing
max_detections300per image

What happens: the image is letterboxed (resized keeping its aspect ratio, padded grey), run without gradients (weights never change), decoded, filtered by confidence, cleaned with class-aware NMS, and mapped back to the original pixels. Evaluation uses exactly the same preprocessing. FP32, FP16 and INT8 models all predict the same way.

Output on disk: results/<image name>.png with boxes and labels, and results/predictions.json:

{"predictions": [{"image": "image.jpg", "width": 640, "height": 480, "annotated": "results/image.png",
  "detections": [{"class_id": 1, "class": "square", "confidence": 0.94, "xyxy": [138.0, 91.0, 206.0, 159.0]}]}]}

A list input returns Predictions (a list of Results with .show() and .to_dict()).

Unreadable inputs raise a DataError naming the file: missing files, unsupported extensions, damaged images. OpenCV frames are BGR; convert with cv2.cvtColor(frame, cv2.COLOR_BGR2RGB) (the generated scripts do).
